# AI tooling: Claude Code, Codex, OpenCode

All three tools get the same instructions, subagents, skills, MCP servers, and approval gates. Every tool-specific file is either native discovery of a canonical file or generated from one. Cursor is not supported; do not add `.cursor/` config.

## Canonical sources (edit these only)

| What | Canonical file | Notes |
| --- | --- | --- |
| Instructions | `AGENTS.md` | Read natively by Codex and OpenCode. Claude Code reads it via `CLAUDE.md` (`@AGENTS.md` import), because a `CLAUDE.md` disables Claude's native `AGENTS.md` loading. |
| Subagents | `.claude/agents/<name>.md` | Frontmatter: `name` (= file name), `description`, `mode: subagent`. No `model` (all tools inherit the session model) and no tool-specific fields. |
| Skills | `.claude/skills/<name>/SKILL.md` | Agent Skills standard. `name` must match the directory. |
| MCP servers + approval gates | `.agent-docs/agent-config.json` | `mcpServers` (remote: `url` + optional `bearerTokenEnv`; stdio: `command`, `args`, `envFromShell`, `env`), `requireApproval` per server, `shellCommandsRequiringApproval` as word-prefix arrays. |

After editing any of them, run `pnpm agents:sync`. CI runs `pnpm agents:check` and fails on drift. Never hand-edit generated files.

## What each tool loads

| | Claude Code | Codex | OpenCode |
| --- | --- | --- | --- |
| Instructions | `CLAUDE.md` → `@AGENTS.md` | `AGENTS.md` | `AGENTS.md` |
| Subagents | `.claude/agents/` | `.codex/agents/*.toml` (generated) | `.opencode/agents/` (symlinks) |
| Skills | `.claude/skills/` | `.agents/skills/` (symlinks) | `.claude/skills/` + `.agents/skills/` |
| MCP | `.mcp.json` | `.codex/config.toml` | `opencode.json` (`mcp.servers`) |
| Shell approval | `.claude/settings.json` `permissions.ask` | `.codex/rules/project.rules` (`decision = "prompt"`) | `opencode.json` `permissions` (`shell`, `ask`) |
| MCP approval | `.claude/settings.json` (`mcp__<server>`) | `default_tools_approval_mode = "prompt"` | `opencode.json` `permissions` (`<server>_*`, `ask`; non-alphanumeric characters in the server name become `?` so the rule matches whichever character OpenCode uses) |

Every row except instructions and skills is generated by `scripts/sync-agent-config.mjs`. Generated: `.mcp.json`, `.codex/config.toml`, `.codex/rules/project.rules`, `.codex/agents/*.toml`, `.claude/settings.json`, `opencode.json`, and the symlinks in `.opencode/agents/` and `.agents/skills/`.

OpenCode sees skills twice (`.claude/skills` and the `.agents/skills` symlinks Codex needs); both resolve to the same files.

## Placeholder syntax (handled by the generator)

| File | Env placeholder |
| --- | --- |
| `.mcp.json` | `${VAR}` |
| `.codex/config.toml` | `bearer_token_env_var = "VAR"`, `env_vars = ["VAR"]` |
| `opencode.json` | `{env:VAR}` |

Required env vars: `GITHUB_MCP_TOKEN`, `LINEAR_MCP_TOKEN`, `CONTEXT7_API_KEY`, `CLOUDFLARE_API_TOKEN`, `DOKPLOY_URL`, `DOKPLOY_API_KEY`. Keep the README "AI coding tools" list in sync when these change.

## Trust (per machine, not in the repo)

- **Claude Code:** approve the project MCP servers on first run.
- **Codex:** trust the project on first run. Until then the whole `.codex/` layer (MCP, rules, agents) is skipped.
- **OpenCode:** no trust step.

## Verify after changes

- `pnpm agents:check` passes.
- `opencode debug agents` lists `frontend-architect` as `subagent` with a clean system prompt; `opencode debug config` shows the project `mcp.servers`.
- `codex mcp list` (trusted) shows the project servers; `codex execpolicy check --rules .codex/rules/project.rules git commit -m x` returns `prompt`.
- `claude mcp list` shows the project servers.

## Policy

- Do not add GitHub Copilot-specific MCP endpoints or agent files.
- Do not add tool-specific rule files that restate `AGENTS.md`; put shared guidance in `AGENTS.md`.
